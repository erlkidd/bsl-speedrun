# bsl-speedrun.kz — архитектура и стек

## Ключевая идея
Статический фронт со всем контентом (задачи, тесты, база знаний) + маленький бэкенд, который
запускает OneScript в одноразовом Docker-контейнере без сети и файлов + BSL Language Server для линтера.
Всё в одном docker compose на VPS, HTTPS на домене автоматически через Caddy.

## Стек
| Слой | Что | Почему |
|---|---|---|
| Фронт | **Astro + React** (острова), TypeScript | БЗ и теория пишутся в Markdown/MDX, страницы статичные и быстрые; интерактив (редактор, квиз) — React |
| Редактор | **Monaco** + подсветка BSL (Monarch-грамматика) | тот же движок, что в VS Code |
| Линтер | **BSL Language Server** в режиме `websocket` + `monaco-languageclient` | живые диагностики, автодополнение, hover — как в VS Code |
| Синтаксис | `oscript -check` на бэке + ошибки парсера BSL LS в редакторе | двойная проверка |
| Выполнение | **OneScript 2.x** в Docker | настоящий движок BSL без платформы |
| API | **Node.js + Fastify** (TS) | общий язык с фронтом, просто спаунить контейнеры |
| Прогресс | MVP: localStorage → позже SQLite + вход (GitHub/Google/email) | не нужно сразу |
| Хостинг | VPS 2 vCPU / 4 ГБ, Ubuntu, **Docker Compose + Caddy** | Caddy сам получает Let's Encrypt для домена |

## Схема
```
Браузер ──HTTPS──> Caddy ─┬─ /            → статика Astro
                          ├─ /api/run     → api (Fastify) → docker run oscript (песочница)
                          ├─ /api/check   → api → oscript + тест-харнесс задачи
                          └─ /lsp (wss)   → bsl-language-server (websocket)
```

## Песочница OneScript (безопасность)
Главная защита — контейнер, а не фильтр слов:
```
docker run --rm --network none --read-only --tmpfs /tmp:size=8m \
  --memory 128m --cpus 0.5 --pids-limit 64 --user 1000:1000 \
  --cap-drop ALL --security-opt no-new-privileges \
  bsl-runner oscript /code/main.os      # таймаут 5 с, вывод обрезать до 64 КБ
```
Дополнительно (defense in depth) — статический запрет до запуска: `КомандаСистемы`, `ЗапуститьПриложение`,
`Новый Файл/ЧтениеТекста/ЗаписьТекста/HTTPСоединение/COMОбъект`, `ПодключитьСценарий`, `ЗагрузитьСценарий`,
`#Использовать`, `Выполнить`/`Вычислить`. Очередь + лимит запросов по IP (rate limit) в API.
`Сообщить()` → stdout → показываем в консоли на странице.

## Практика: формат задачи
Каждая задача — папка в репозитории:
```
tasks/011-sum-array/
  task.md          # условие (Markdown)
  meta.yaml        # сложность, теги, подсказки[], запреты/требования
  starter.os       # заготовка: Функция СуммаМассива(Массив) Экспорт ... КонецФункции
  solution.os      # эталон (показывается по кнопке)
  tests.os         # харнесс: вызывает функцию ученика на наборах данных
```
Проверка «по-своему» = 3 уровня:
1. **Синтаксис** — `oscript -check`.
2. **Правила задачи** (meta.yaml): обязательные/запрещённые конструкции (напр. «использовать `Для Каждого`»,
   «без `Запрос` в цикле»), выбранные диагностики BSL LS считаются ошибкой.
3. **Тесты** — код ученика + `tests.os` в одном контейнере; харнесс печатает JSON
   `{passed, failed, cases:[{input, expected, actual}]}`, фронт показывает таблицу кейсов.

## Теория (квиз)
`quiz/*.yaml`: вопрос, варианты, правильный, объяснение для каждого неверного.
Неверный ответ → подсвечиваем правильный + показываем объяснение + ссылку на статью БЗ. Всё на клиенте, без бэка.

## База знаний
`kb/general/*.mdx` и `kb/bsp/*.mdx` — Astro Content Collections: навигация, поиск (Pagefind, статический),
блоки кода с подсветкой BSL, кнопка «Открыть в песочнице».

## Хостинг на домене
1. VPS (ps.kz / Hoster.kz — ближе к КЗ, или Hetzner), Ubuntu 24.04, ставим Docker.
2. У регистратора домена: A-запись `bsl-speedrun.kz` (и `www`) → IP VPS.
3. `git clone` + `docker compose up -d` — Caddy сам выпустит сертификат.
4. Деплой обновлений: GitHub Actions → ssh → `git pull && docker compose up -d --build`.

## Этапы
1. **Песочница**: Monaco + `/api/run` + Docker-раннер. (ядро, всё остальное на нём)
2. **Линтер**: BSL LS websocket в Monaco.
3. **Практика**: формат задач, харнесс, 10–15 первых задач.
4. **Теория-квиз** + **БЗ** (контент можно писать параллельно).
5. Аккаунты и прогресс, рейтинг/«спидран»-таймер.

## Риски, проверить прототипом
- Как BSL LS websocket держит несколько клиентов одновременно (при проблеме — пул процессов или линт по запросу
  через постоянно запущенный BSL LS).
- Память: BSL LS (Java) ~0.5–1 ГБ → VPS не меньше 4 ГБ.
- Холодный старт `docker run` ~0.3–0.7 с — для MVP нормально, позже пул «тёплых» контейнеров.
