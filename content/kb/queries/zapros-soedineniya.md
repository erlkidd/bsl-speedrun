## Четыре вида соединений

| Вид | Что остаётся |
|---|---|
| `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` | только строки, для которых нашлась пара |
| `ЛЕВОЕ СОЕДИНЕНИЕ` | все строки левой таблицы; нет пары — справа NULL |
| `ПРАВОЕ СОЕДИНЕНИЕ` | зеркально: все строки правой |
| `ПОЛНОЕ СОЕДИНЕНИЕ` | все строки обеих таблиц |

Условие соединения пишут после `ПО`.

```query
ВЫБРАТЬ
    Ном.Наименование КАК Товар,
    ШК.Штрихкод
ИЗ
    Справочник.Номенклатура КАК Ном
        ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ШтрихкодыНоменклатуры КАК ШК
        ПО ШК.Номенклатура = Ном.Ссылка
ГДЕ
    НЕ Ном.ЭтоГруппа
```

Обрати внимание на результат: у смартфона два штрихкода — он занимает две строки. **Соединение размножает строки** левой таблицы по числу совпадений справа.

## Декартово произведение

Таблицы через запятую без условия — каждая строка с каждой:

```query
ВЫБРАТЬ
    Вал.Наименование КАК Валюта,
    Скл.Наименование КАК Склад
ИЗ
    Справочник.Валюты КАК Вал,
    Справочник.Склады КАК Скл
```

4 валюты × 3 склада = 12 строк. На реальных таблицах это миллионы строк и зависший запрос. Если такой результат получился случайно — забыто условие соединения.

## Антисоединение: «у кого нет»

```query
ВЫБРАТЬ
    Контр.Наименование
ИЗ
    Справочник.Контрагенты КАК Контр
        ЛЕВОЕ СОЕДИНЕНИЕ Документ.РеализацияТоваров КАК Док
        ПО Док.Контрагент = Контр.Ссылка
ГДЕ
    Док.Ссылка ЕСТЬ NULL
    И НЕ Контр.ЭтоПоставщик
```

## ПО или ГДЕ — главная ловушка левого соединения

Условие на **правую** таблицу в `ГДЕ` отбрасывает строки с NULL, и левое соединение превращается во внутреннее.

```query
// Склады без июньских реализаций пропадут
ВЫБРАТЬ
    Скл.Наименование КАК Склад,
    КОЛИЧЕСТВО(Док.Ссылка) КАК Документов
ИЗ
    Справочник.Склады КАК Скл
        ЛЕВОЕ СОЕДИНЕНИЕ Документ.РеализацияТоваров КАК Док
        ПО Док.Склад = Скл.Ссылка
ГДЕ
    Док.Дата >= ДАТАВРЕМЯ(2026, 6, 1)
СГРУППИРОВАТЬ ПО
    Скл.Наименование
```

Правильно — перенести условие в `ПО`:

```query
ВЫБРАТЬ
    Скл.Наименование КАК Склад,
    КОЛИЧЕСТВО(Док.Ссылка) КАК Документов
ИЗ
    Справочник.Склады КАК Скл
        ЛЕВОЕ СОЕДИНЕНИЕ Документ.РеализацияТоваров КАК Док
        ПО Док.Склад = Скл.Ссылка
            И Док.Дата >= ДАТАВРЕМЯ(2026, 6, 1)
СГРУППИРОВАТЬ ПО
    Скл.Наименование
```

`КОЛИЧЕСТВО(Док.Ссылка)` не считает NULL — у пустого склада будет 0. `КОЛИЧЕСТВО(*)` дал бы 1.

## ОБЪЕДИНИТЬ

Объединение ставит результаты запросов **друг под другом**. Число полей должно совпадать, имена колонок берутся из первого запроса.

```query
ВЫБРАТЬ
    "Поступление" КАК Вид, Номер, Дата, СуммаДокумента
ИЗ
    Документ.ПоступлениеТоваров
ГДЕ
    Проведен

ОБЪЕДИНИТЬ ВСЕ

ВЫБРАТЬ
    "Реализация", Номер, Дата, СуммаДокумента
ИЗ
    Документ.РеализацияТоваров
ГДЕ
    Проведен

УПОРЯДОЧИТЬ ПО
    Дата
```

`ОБЪЕДИНИТЬ` (без `ВСЕ`) дополнительно убирает одинаковые строки — это лишняя работа для СУБД. Если дубли невозможны или нужны, пиши `ОБЪЕДИНИТЬ ВСЕ`.

## Правила

- Не соединяй с вложенным запросом — вынеси его во [временную таблицу](/kb/queries/zapros-vremennye-tablicy).
- Поля правой таблицы после левого соединения оборачивай в `ЕСТЬNULL`.
- Не прячь дубли через `РАЗЛИЧНЫЕ` — найди соединение, которое их создало.
