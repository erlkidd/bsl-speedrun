Регистр накопления хранит **движения** — изменения числовых показателей. Два вида:

| Вид | Что хранит | Пример | Виртуальные таблицы |
|---|---|---|---|
| Остатки | приход и расход | ТоварыНаСкладах, Взаиморасчеты | Остатки, Обороты, ОстаткиИОбороты |
| Обороты | только накопленные обороты | Продажи | Обороты |

У записи есть `Период`, `Регистратор` (документ-владелец движения), измерения, ресурсы, а у регистра остатков — ещё `ВидДвижения` (Приход / Расход).

## Физическая таблица — сами движения

```query
ВЫБРАТЬ
    Период,
    Регистратор,
    ВидДвижения,
    Склад,
    Количество
ИЗ
    РегистрНакопления.ТоварыНаСкладах
ГДЕ
    Номенклатура = ЗНАЧЕНИЕ(Справочник.Номенклатура.Ноутбук)
УПОРЯДОЧИТЬ ПО
    Период
```

Нужна, когда важны отдельные записи. Итоги по ней считать не надо — для этого есть виртуальные таблицы, они пользуются хранимыми итогами регистра.

## Остатки

`Остатки(Период, Условие)` — приход минус расход на момент времени.

```query
ВЫБРАТЬ
    Номенклатура,
    Склад,
    КоличествоОстаток
ИЗ
    РегистрНакопления.ТоварыНаСкладах.Остатки(&Дата, Склад = &Склад)
```

- Имя ресурса получает суффикс: `Количество` → `КоличествоОстаток`.
- Период не указан — остаток «сейчас».
- Остаток считается на **начало** указанного момента: движения самой этой секунды не входят.
- Измерения, которые не выбраны в запросе, сворачиваются: без поля `Склад` получишь остаток по всем складам сразу.

## Обороты

`Обороты(НачалоПериода, КонецПериода, Периодичность, Условие)`.

```query
ВЫБРАТЬ
    Период,
    КоличествоОборот,
    СуммаОборот
ИЗ
    РегистрНакопления.Продажи.Обороты(&Начало, &Конец, Месяц)
УПОРЯДОЧИТЬ ПО
    Период
```

Периодичность (`День`, `Неделя`, `Месяц`, `Квартал`, `Год`, `Регистратор`) добавляет поле `Период` — начало соответствующего интервала. У регистра остатков, кроме `…Оборот`, есть `…Приход` и `…Расход`.

## ОстаткиИОбороты

`ОстаткиИОбороты(НачалоПериода, КонецПериода, Периодичность, МетодДополнения, Условие)` — ведомость: что было, что пришло, что ушло, что осталось.

```query
ВЫБРАТЬ
    Номенклатура,
    КоличествоНачальныйОстаток,
    КоличествоПриход,
    КоличествоРасход,
    КоличествоКонечныйОстаток
ИЗ
    РегистрНакопления.ТоварыНаСкладах.ОстаткиИОбороты(&Начало, &Конец)
```

## Главное правило: отбор — в параметры

```query
// Медленно: остатки по всему регистру, потом отбор
ВЫБРАТЬ Номенклатура, КоличествоОстаток
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки()
ГДЕ Склад = &Склад
```

```query
// Правильно: отбор применяется до расчёта
ВЫБРАТЬ Номенклатура, КоличествоОстаток
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад)
```

Результат одинаковый, а нагрузка на СУБД отличается на порядки. А вот условие на уже посчитанный остаток — это `ГДЕ`:

```query
ВЫБРАТЬ Номенклатура, КоличествоОстаток
ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад)
ГДЕ КоличествоОстаток < 10
```

## Регистратор и ВЫРАЗИТЬ

`Регистратор` — поле составного типа. Точка от него соединяет запрос со всеми документами-регистраторами. Сужай тип:

```query
ВЫБРАТЬ
    Период,
    ВЫРАЗИТЬ(Регистратор КАК Документ.РеализацияТоваров).Контрагент КАК Покупатель,
    Количество
ИЗ
    РегистрНакопления.ТоварыНаСкладах
ГДЕ
    Регистратор ССЫЛКА Документ.РеализацияТоваров
```

## Суффиксы ресурсов

| Таблица | Суффиксы |
|---|---|
| Остатки | `Остаток` |
| Обороты | `Оборот`, а у регистра остатков ещё `Приход`, `Расход` |
| ОстаткиИОбороты | `НачальныйОстаток`, `Приход`, `Расход`, `Оборот`, `КонечныйОстаток` |
