Временная таблица — это результат запроса, сохранённый под именем, чтобы следующие запросы читали его как обычную таблицу. Способ разложить сложную выборку на простые шаги.

## Синтаксис

```query
// Шаг 1: продажи по товарам — во временную таблицу
ВЫБРАТЬ
    Номенклатура,
    СУММА(Количество) КАК Продано
ПОМЕСТИТЬ втПродажи
ИЗ
    РегистрНакопления.Продажи
СГРУППИРОВАТЬ ПО
    Номенклатура
ИНДЕКСИРОВАТЬ ПО
    Номенклатура
;

// Шаг 2: читаем её и соединяем с остатками
ВЫБРАТЬ
    втПродажи.Номенклатура,
    втПродажи.Продано,
    ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК НаСкладе
ИЗ
    втПродажи
        ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
        ПО втПродажи.Номенклатура = Остатки.Номенклатура
```

- `ПОМЕСТИТЬ Имя` стоит после списка полей, перед `ИЗ`.
- Запросы пакета разделяет `;`. Они выполняются по порядку, каждый видит таблицы предыдущих.
- Запрос с `ПОМЕСТИТЬ` наружу данные **не возвращает** — он только наполняет таблицу.
- `ИНДЕКСИРОВАТЬ ПО` строит индекс по полям соединения; нужен для больших таблиц.
- Имена принято начинать с `вт`.

В [консоли](/queries) у каждого запроса пакета своя вкладка: во вкладке «ВТ» видно, что именно лежит во временной таблице.

## Отбор по временной таблице

Подзапрос к временной таблице можно передать прямо в параметры виртуальной таблицы — отбор применится до расчёта остатков:

```query
ВЫБРАТЬ
    Ссылка КАК Товар
ПОМЕСТИТЬ втТовары
ИЗ
    Справочник.Номенклатура
ГДЕ
    Родитель = ЗНАЧЕНИЕ(Справочник.Номенклатура.БытоваяТехника)
;

ВЫБРАТЬ
    Номенклатура,
    КоличествоОстаток
ИЗ
    РегистрНакопления.ТоварыНаСкладах.Остатки(,
        Номенклатура В (ВЫБРАТЬ Товар ИЗ втТовары))
```

## УНИЧТОЖИТЬ

```query
ВЫБРАТЬ Ссылка, СуммаДокумента
ПОМЕСТИТЬ втКрупные
ИЗ Документ.РеализацияТоваров
ГДЕ Проведен И СуммаДокумента > 1500000
;
ВЫБРАТЬ Ссылка, СуммаДокумента ИЗ втКрупные
;
УНИЧТОЖИТЬ втКрупные
```

## Время жизни

- Без менеджера временных таблиц — до конца пакета.
- С `МенеджерВременныхТаблиц` — пока жив менеджер или пока таблицу не уничтожили. Один менеджер можно назначить нескольким запросам.

```bsl
Менеджер = Новый МенеджерВременныхТаблиц;

Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = Менеджер;
Запрос.Текст = "ВЫБРАТЬ Ссылка КАК Товар ПОМЕСТИТЬ втТовары ИЗ Справочник.Номенклатура";
Запрос.Выполнить();

ВторойЗапрос = Новый Запрос;
ВторойЗапрос.МенеджерВременныхТаблиц = Менеджер;
ВторойЗапрос.Текст = "ВЫБРАТЬ Товар ИЗ втТовары";   // видит ту же таблицу
```

## Зачем они нужны

1. **Вместо вложенных запросов в соединениях.** Оптимизатор СУБД не знает размер вложенного запроса и нередко выбирает медленный план. У временной таблицы есть статистика и индекс.
2. **Вместо запроса в цикле.** Таблицу значений передают параметром и первым шагом превращают во временную: `ВЫБРАТЬ … ПОМЕСТИТЬ втДанные ИЗ &Таблица КАК Т`.
3. **Для читаемости и отладки.** Каждый шаг можно выполнить отдельно и посмотреть, что получилось.

## Чего не делать

- Не создавать и не уничтожать временные таблицы в цикле.
- Не складывать в них «всё на всякий случай» — только нужные строки и колонки.
- Не забывать `ПОМЕСТИТЬ`: без него следующий запрос упадёт с «таблица не найдена».
