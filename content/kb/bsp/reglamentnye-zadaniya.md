Регламентное задание запускает **планировщик по расписанию**, без пользователя. Не путать с длительной операцией — её запускает действие пользователя, а форма ждёт результат.

| Модуль | Для чего |
|---|---|
| `РегламентныеЗаданияСервер` | программный интерфейс — его и вызывают |
| `РегламентныеЗаданияПереопределяемый` | точка расширения: свои задания и настройки |

Модуля `РегламентныеЗадания` без суффикса в БСП нет (так называется менеджер платформы). Клиентского публичного интерфейса у механизма тоже нет.

## Объявить своё задание

1. Создать объект метаданных «Регламентное задание»; обработчик — в общем модуле, указан в свойстве `ИмяМетода`.
2. Описать задание для библиотеки в хуке переопределяемого модуля:

```bsl
// РегламентныеЗаданияПереопределяемый — тело хука, его вызывает библиотека
Процедура ПриОпределенииНастроекРегламентныхЗаданий(Настройки) Экспорт
	Настройка = Настройки.Добавить();
	Настройка.МетаданныеЗадания = Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют;
КонецПроцедуры
```

Хук реализуют, а не вызывают по имени из своего кода.

## Найти, включить, выключить

```bsl
Задание = Метаданные.РегламентныеЗадания.ЗагрузкаКурсовВалют;
Если РегламентныеЗаданияСервер.РегламентноеЗаданиеИспользуется(Задание) Тогда
	РегламентныеЗаданияСервер.УстановитьИспользованиеРегламентногоЗадания(Задание, Ложь);
КонецЕсли;

Отбор = Новый Структура("Метаданные", Задание);
Задания = РегламентныеЗаданияСервер.НайтиЗадания(Отбор);
```

- Не меняйте `Использование` у объекта задания напрямую: в модели сервиса задания лежат в очереди заданий, и правка не подействует. Функции библиотеки скрывают это различие.
- По той же причине не используйте платформенный `РегламентныеЗадания.НайтиРегламентныеЗадания` — пользуйтесь `НайтиЗадания`. Он возвращает массив в локальном режиме и таблицу значений в модели сервиса.
- Выключение не прерывает уже запущенное выполнение — задание просто не запустится снова.
