Три способа доработать типовую конфигурацию, не ломая обновления.

## Расширения

Объекты основной конфигурации **заимствуются** в расширение, после чего их можно дополнять.

| Аннотация | Что делает |
|---|---|
| `&Перед("Метод")` | ваш код до типового |
| `&После("Метод")` | ваш код после типового |
| `&Вместо("Метод")` | ваш код вместо типового; исходный — через `ПродолжитьВызов()` |
| `&ИзменениеИКонтроль("Метод")` | правка текста метода (`#Вставка` / `#Удаление`) с контролем при обновлении |

```bsl
&После("ОбработкаПроведения")
Процедура МоеРасширение_ОбработкаПроведения(Отказ, РежимПроведения)
	Если Отказ Тогда
		Возврат;
	КонецЕсли;
	// дополнительные движения
КонецПроцедуры
```

## Подписки на события

Объект метаданных «Подписка на событие»: источники (типы), событие (`ПередЗаписью`, `ОбработкаПроведения`...), обработчик в общем модуле.

- Удобно, когда одна логика нужна многим объектам.
- Порядок выполнения нескольких подписок не гарантирован.
- Подписка на частое событие с тяжёлым кодом замедляет запись всех источников.

## Переопределяемые модули БСП

Точки расширения БСП: `...Переопределяемый` (`ОбщегоНазначенияПереопределяемый`, `УправлениеПечатьюПереопределяемый` и др.). Свой код пишется туда — сами модули библиотеки не трогают, и обновление БСП проходит проще.
