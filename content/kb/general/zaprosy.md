## Правила, которые спрашивают на каждом собеседовании

1. **Нет запросов в цикле.** Один запрос с параметром-массивом или временной таблицей вместо N запросов.
2. **Отбор в параметрах виртуальных таблиц**, а не в `ГДЕ`.
3. **Нет соединений с вложенными запросами** — материализуйте их во временную таблицу (`ПОМЕСТИТЬ`, при необходимости `ИНДЕКСИРОВАТЬ ПО`).
4. **Осторожно с «точкой» от составных полей** — используйте `ВЫРАЗИТЬ`.
5. **`ОБЪЕДИНИТЬ ВСЕ`** вместо `ОБЪЕДИНИТЬ`, если дубликаты не мешают.
6. **Условия по индексируемым полям**, без функций над полем в `ГДЕ` (`ГОД(Дата) = 2026` не использует индекс — лучше `Дата МЕЖДУ &Начало И &Конец`).

## Пакетный запрос с временной таблицей

```bsl
Запрос = Новый Запрос;
Запрос.УстановитьПараметр("Товары", МассивТоваров);
Запрос.Текст =
"ВЫБРАТЬ
|	Номенклатура.Ссылка КАК Номенклатура
|ПОМЕСТИТЬ ВТТовары
|ИЗ
|	Справочник.Номенклатура КАК Номенклатура
|ГДЕ
|	Номенклатура.Ссылка В (&Товары)
|ИНДЕКСИРОВАТЬ ПО
|	Номенклатура
|;
|ВЫБРАТЬ
|	ВТТовары.Номенклатура,
|	ЕСТЬNULL(Цены.Цена, 0) КАК Цена
|ИЗ
|	ВТТовары КАК ВТТовары
|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&Дата, Номенклатура В (&Товары)) КАК Цены
|		ПО ВТТовары.Номенклатура = Цены.Номенклатура";
Выборка = Запрос.Выполнить().Выбрать();
```

## Вложенные запросы

**Не ставьте вложенный запрос в список полей** — он выполняется для каждой строки внешнего запроса. Соединение СУБД выполняет одной операцией.

```bsl
// медленно: подзапрос с агрегатом на каждую строку
"ВЫБРАТЬ
|	Номенклатура.Ссылка,
|	(ВЫБРАТЬ СУММА(Остатки.Количество) …) КАК Остаток
|ИЗ
|	Справочник.Номенклатура КАК Номенклатура"

// быстро: соединение с уже агрегированной виртуальной таблицей
"ВЫБРАТЬ
|	Номенклатура.Ссылка КАК Номенклатура,
|	ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
|ИЗ
|	Справочник.Номенклатура КАК Номенклатура
|		ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки КАК Остатки
|		ПО Номенклатура.Ссылка = Остатки.Номенклатура"
```

Виртуальная таблица `Остатки` берёт данные из таблицы итогов — это дешевле, чем суммировать движения в подзапросе.

Многошаговую обработку (несколько источников, повторное использование промежуточного результата) раскладывайте по **временным таблицам**.

## Соединения

| Соединение | Результат |
|---|---|
| `ВНУТРЕННЕЕ` | только строки, у которых есть пара |
| `ЛЕВОЕ` | все строки левой таблицы, справа NULL, если пары нет |
| `ПОЛНОЕ` | все строки обеих таблиц |

`ГДЕ` фильтрует до группировки, `ИМЕЮЩИЕ` — после.
