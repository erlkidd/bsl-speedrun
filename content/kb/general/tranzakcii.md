В 1С нет автоматического управления ручными транзакциями: начало, фиксацию и откат пишет разработчик. Каждая незакрытая транзакция — заблокированные записи и ошибки у других сеансов.

## Исключения: логировать, а не глотать

Пустой блок `Исключение` — самый опасный антипаттерн: данные не записаны, пользователь не знает, в журнале нет следов.

```bsl
Попытка
	ДокументОбъект.Записать(РежимЗаписиДокумента.Проведение);
Исключение
	ЗаписьЖурналаРегистрации(НСтр("ru = 'Проведение документа'"),
		УровеньЖурналаРегистрации.Ошибка, ДокументОбъект.Метаданные(), ДокументОбъект.Ссылка,
		ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	ВызватьИсключение;
КонецПопытки;
```

| | Куда |
|---|---|
| `ПодробноеПредставлениеОшибки` | в журнал регистрации: стек, строки, вложенные ошибки |
| `КраткоеПредставлениеОшибки` | пользователю, вместе с понятным текстом «что делать» |
| `ВызватьИсключение;` | промежуточный код: проброс исходной ошибки со стеком |
| `ВызватьИсключение "Текст";` | граница с пользователем: заменить технический текст понятным |

## Канонический шаблон транзакции

```bsl
НачатьТранзакцию();
Попытка
	// 1. блокировка  2. чтение и изменение  3. запись
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	ЗаписьЖурналаРегистрации(…, ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
	ВызватьИсключение;
КонецПопытки;
```

| Правило | Почему |
|---|---|
| `НачатьТранзакцию()` вплотную перед `Попытка` | ошибка между ними оставит транзакцию открытой |
| `ЗафиксироватьТранзакцию()` — последний оператор перед `Исключение` | ошибка после фиксации попадёт в `Исключение`, а откатывать уже нечего |
| `ОтменитьТранзакцию()` — первый оператор в `Исключение` | логирование тоже может упасть — сначала закрываем транзакцию |
| пробрасывать `ВызватьИсключение;` | внешний код должен узнать об ошибке |

**Вложенные транзакции счётчиковые.** Вложенный `НачатьТранзакцию()` лишь увеличивает счётчик. `ОтменитьТранзакцию()` на любом уровне помечает всю транзакцию отменённой — последующий `ЗафиксироватьТранзакцию()` даже снаружи вызовет исключение. Проверка `ТранзакцияАктивна()` не заменяет правильный шаблон.

**Транзакция — короткая.** Подготовку данных и проверки делают до неё; внутри — только быстрые записи. Внешние HTTP-вызовы внутри транзакции недопустимы: таймаут ответа = время блокировки.

## Управляемая блокировка: заблокировать → прочитать → записать

```bsl
Блокировка = Новый БлокировкаДанных;
Элемент = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
Элемент.УстановитьЗначение("Номенклатура", Номенклатура);
Элемент.УстановитьЗначение("Склад", Склад);
Элемент.Режим = РежимБлокировкиДанных.Исключительный;
Блокировка.Заблокировать();
// теперь читаем остаток — другой сеанс его не изменит до конца транзакции
```

Без блокировки два сеанса прочитают остаток 10, один спишет 8, другой 7 — уйдём в минус. С блокировкой второй сеанс дождётся первого, прочитает 2 и получит корректную ошибку.

| Режим | Совместим с |
|---|---|
| Разделяемый | другими разделяемыми |
| Исключительный | ни с чем |

`ЗаблокироватьДанныеДляРедактирования(Ссылка)` — другое: пессимистическая блокировка объекта целиком, второй пользователь получит «Объект заблокирован», а не потерянное обновление.

## Взаимоблокировки

Возникают, когда транзакции захватывают ресурсы в разном порядке. Помогает:

- **единый порядок** — сортировать ключи перед блокировкой (задача [«Единый порядок блокировок»](/practice/023-lock-order));
- сразу ставить исключительную блокировку на то, что будете менять, а не повышать разделяемую;
- короткие транзакции.

## Массовые операции

Одна большая транзакция на всю пачку держит блокировки долго и откатывает всё из-за одной ошибки. Правильно: транзакция на каждый элемент, ошибки копятся в список и пишутся в журнал, обработка продолжается, в конце — список ошибок пользователю (задача [«Массовая обработка без остановки»](/practice/024-bulk-errors)).

## Объектные блокировки при записи

- **Оптимистическая** — при записи проверяется версия: «Объект изменён или удалён другим пользователем».
- **Пессимистическая** — `Объект.Заблокировать()` или `ЗаблокироватьДанныеДляРедактирования`: пока объект открыт на редактирование, другие его не запишут.
