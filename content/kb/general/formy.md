Главный принцип: **меньше серверных вызовов и меньше данных в каждом.** Вызов `&НаСервере` — это сетевой обмен плюс передача всего контекста формы туда и обратно.

## Какую директиву выбрать

```
Нужна база данных?
├── Нет  → &НаКлиенте или &НаКлиентеНаСервереБезКонтекста
└── Да   → Нужны реквизиты формы?
           ├── Нет → &НаСервереБезКонтекста (передаются только параметры)
           └── Да  → &НаСервере (передаётся весь контекст)
```

```bsl
// Чистое вычисление — работает и на клиенте, и на сервере
&НаКлиентеНаСервереБезКонтекста
Функция СуммаСтроки(Количество, Цена)
	Возврат Количество * Цена;
КонецФункции
```

## Один вызов вместо нескольких

При смене контрагента нужно заполнить договор, организацию, валюту, курс — это **один** серверный вызов, возвращающий Структуру, а не четыре.

```bsl
&НаКлиенте
Процедура КонтрагентПриИзменении(Элемент)
	Данные = ДанныеПоКонтрагенту(Объект.Контрагент);
	Объект.Договор = Данные.Договор;
	Объект.Организация = Данные.Организация;
КонецПроцедуры

&НаСервереБезКонтекста
Функция ДанныеПоКонтрагенту(Контрагент)
	Реквизиты = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Контрагент, "ДоговорПоУмолчанию, ОсновнаяОрганизация");
	Возврат Новый Структура("Договор, Организация", Реквизиты.ДоговорПоУмолчанию, Реквизиты.ОсновнаяОрганизация);
КонецФункции
```

Видимость и доступность элементов меняют тоже одним вызовом — иначе интерфейс «дёргается».

## Объект формы и настоящий объект

На сервере формы `Объект` — это `ДанныеФормы…`, а не объект. Чтобы вызвать метод модуля объекта:

```bsl
&НаСервере
Процедура ЗаполнитьНаСервере()
	ДокументОбъект = РеквизитФормыВЗначение("Объект");
	ДокументОбъект.ЗаполнитьТоварыПоУмолчанию();
	ЗначениеВРеквизитФормы(ДокументОбъект, "Объект"); // без этого изменения потеряются
КонецПроцедуры
```

## Порядок событий

Открытие: `ПриСозданииНаСервере` (сервер, данные загружены) → `ПриОткрытии` (клиент).

Запись: `ПередЗаписью` (клиент) → `ПередЗаписьюНаСервере` → `ПриЗаписиНаСервере` (в транзакции записи) → `ПослеЗаписиНаСервере` → `ПослеЗаписи` (клиент).

## Диалоги без модальности

`Вопрос()` и `Предупреждение()` не работают в веб-клиенте и при отключённой модальности. Используют асинхронные методы:

```bsl
&НаКлиенте
Процедура УдалитьСтроку(Команда)
	ПоказатьВопрос(Новый ОписаниеОповещения("ПослеОтвета", ЭтотОбъект),
		НСтр("ru = 'Удалить строку?'"), РежимДиалогаВопрос.ДаНет);
КонецПроцедуры

&НаКлиенте
Процедура ПослеОтвета(Ответ, ДополнительныеПараметры) Экспорт
	Если Ответ = КодВозвратаДиалога.Да Тогда
		// удаляем
	КонецЕсли;
КонецПроцедуры
```

Результат другой формы получают так же: `ОткрытьФорму(Имя, Параметры, ЭтотОбъект, , , , Новый ОписаниеОповещения(...))`.

## Оповещения между формами

Форма документа после записи вызывает `Оповестить("Запись_Документ", Параметр, ЭтотОбъект)`, форма списка ловит событие в `ОбработкаОповещения` и обновляет список.

## Что можно передать между клиентом и сервером

- **Можно:** примитивы, ссылки, перечисления, `Структура`, `Соответствие`, `Массив`, фиксированные коллекции, `ХранилищеЗначения`.
- **Нельзя:** `ТаблицаЗначений`, `ДеревоЗначений` (на форме — через реквизиты формы), `ОбъектМетаданных` (передают имя строкой), `Запрос`, `РезультатЗапроса`.

## Динамический список

Сам делает постраничную загрузку, поиск и сортировку. Отборы из кода задают через компоновку данных — например, `ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбораДинамическогоСписка`, а не дописывая `ГДЕ` в текст запроса.
